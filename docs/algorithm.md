# 最適位置探索アルゴリズム

## 概要

対象店舗を固定した他店舗の位置を所与として、自分の顧客数が最大になるグリッド座標を全探索で求める（`findBestPosition`）。

## 距離の定義

住民と候補座標の近さを測る基準で、次元ごとに異なる。

| 次元 | 距離関数 |
|---|---|
| 1次元 | $d(a, b) = \|a - b\|$（絶対値距離） |
| 2次元 | $d(a, b) = \sqrt{(a_x - b_x)^2 + (a_y - b_y)^2}$（ユークリッド距離） |
| 3次元 | $d(a, b) = \sqrt{(a_x - b_x)^2 + (a_y - b_y)^2 + (a_z - b_z)^2}$（ユークリッド距離） |

2次元の内部実装では比較に $d^2$（距離の二乗）を使い、`sqrt` を省略して高速化している。

## アルゴリズム

住民は一番近い店舗を選ぶ。この前提のもと、マップ上の全マスを順番に試して「この位置なら何人の住民が一番近くなるか」を数え、最も多かったマスに移動する。

**手順**

1. 各住民について、他の店舗（対象店舗以外）との距離をそれぞれ計算し、一番近い距離を覚えておく（2店舗・100住民なら 100 × 1 = 100回）
2. 全マスを一つずつ試す
   - 各住民について、そのマスまでの距離と1で覚えた距離を比べる
   - そのマスの方が近ければその住民を獲得
   - 同じ距離なら店舗名のアルファベット順が早い方（A > B > C …）が優先
3. 一番多く獲得できたマスを返す

**1を先にやる理由**

1を先にやっておくと、2の各マスでは「そのマスまでの距離と1の値を比べるだけ」で判定できる。先にやらない場合は全マスで全住民×全店舗の距離を毎回計算し直すため、店舗数が増えるほど遅くなる。
